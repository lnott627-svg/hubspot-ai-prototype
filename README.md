# HubSpot Proactive AI Prototype — "Breeze" Diagnostic Triage

An interactive prototype demonstrating a redesign of HubSpot's Starter-tier
quota experience: instead of a silent auto-upgrade when a user crosses the
1,000 marketing-contact limit, **Breeze AI** intercepts proactively, diagnoses
the situation, and offers one-click remediation (delete low-value records or
merge duplicates) or a conscious upgrade.

## What's in this build (Milestone 1: the functional AI engine)

The UI shell and the deterministic state machine already existed. This
milestone connects a **real LLM (Google Gemini)** to that UI:

- **Live diagnosis + chips.** When the intercept fires, the frontend POSTs the
  live account state to `/api/diagnose`. Gemini writes the diagnostic sentence
  and *chooses which remediation chips to show*.
- **Deterministic math, always.** The model only picks *which* actions to
  offer (by `action_id`); the quota numbers come from the app's own catalogue
  (`CONFIG.triageCategories`). A misbehaving model can never corrupt the
  on-screen math. Bogus/unknown actions returned by the model are discarded.
- **Merge duplicates.** A third remediation path (`merge_dupes`) alongside
  hard-bounced and unengaged cleanup.
- **Silent fallback (pitch-safe).** If the AI call errors, times out (2.5s),
  or returns malformed output, the UI silently reverts to a polished canned
  triage. It never shows a spinner that hangs, an error, or an empty modal —
  so a live demo can't break in front of a client. The prototype even works
  with **no server at all** (open `index.html` directly) via the same
  fallback.

## Milestone 2: the trust & reasoning layer

Additions on top of the AI engine, aimed at the moment a stakeholder asks
"how do I know the AI isn't just making bulk deletes blindly?":

- **Per-chip AI reasoning.** Each remediation category carries its own
  one-sentence "why" from Gemini (e.g. *"Frees 30 and gets you to 920"*),
  not just a generic label. On the fallback path (no AI), the canonical
  static detail text renders in the exact same spot, styled identically —
  so a viewer can't tell which path they're on.
- **Undo.** After a cleanup executes, the confirmation toast carries an
  Undo button for 8 seconds. Undo restores contact counts, marketing
  status, selection state, and the overage countdown exactly as they were —
  the one place a user can walk back an AI-driven bulk action.

## Milestone 3: the Optimize Database page

The original in-modal checklist has been replaced with a dedicated,
full-page review-and-select flow — closer to how HubSpot itself handles
anything destructive, and giving a stakeholder room to actually look at
what's being touched instead of trusting a summary number.

- **Dedicated page, not a modal.** Clicking "Optimize Database" on the
  warning screen runs the same AI scan as before, then routes to
  `/optimize-database` — a real page in the app's own navigation (the
  Contacts sidebar item stays highlighted), not an overlay.
- **Full contact-level review.** Every remediation category (hard-bounced,
  unengaged, duplicates) renders as its own section listing *every* record
  behind that count — name, email, and a specific reason per row — not a
  capped preview. Users can select individual contacts one at a time or hit
  "select all" per section (a proper checked/unchecked/indeterminate
  checkbox), and nothing is pre-selected — the user opts in to every record.
- **A native HubSpot-style confirmation.** Clicking the footer action opens
  a confirmation dialog modeled on HubSpot's own "type the number to
  delete" failsafe: the button stays disabled until the user types the
  *exact* count of records they selected. The title and copy adapt to
  what's actually selected — delete-only, merge-only, or a mixed batch all
  read differently, so the confirmation always describes the real action.
- **Clear return path.** Confirming returns the user to Contacts with a
  toast naming exactly what happened (e.g. "30 inactive contacts
  permanently deleted and 20 duplicates merged"), still backed by the same
  Undo button from Milestone 2. Backing out — the page's back link, or
  Cancel/close/Escape/overlay-click on the confirm dialog — leaves account
  state completely untouched.
- **One page, two origins.** Both the pre-emptive warning screen ("Optimize
  Database to Save…") and the post-breach recovery flow ("Free up
  capacity") route through this same page and resolve correctly for their
  own context.

## Run it

```bash
npm install
# 1) copy .env.example to .env and paste a valid Google AI Studio key (AIza...)
cp .env.example .env
node server.js          # or: npm start
```

Then open http://localhost:3000, go to Contacts, select contacts, and click
**Set as marketing** to trigger the Breeze intercept.

- **Live AI on:** with a valid key, Breeze's diagnosis is generated by Gemini.
- **Live AI off / no key / offline:** the canned triage takes over invisibly.

## Files

- `index.html` — the entire frontend (UI, state machine, AI wiring, fallback).
- `server.js` — Express server: static hosting + `POST /api/diagnose` (Gemini)
  + `GET /api/health`.
- `.env.example` — template for your API key. Real `.env` is git-ignored.

## Notes

- The API key format matters: Google AI Studio keys start with `AIza`. The key
  previously on file returned `403 Forbidden`.
- Model: `gemini-3.7-flash` with JSON response mode (overridable via
  `GEMINI_MODEL`).
